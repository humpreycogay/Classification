What was tested

Banking77 is a collection of short messages that customers sent to an online bank, each tagged with one of 77 reasons for getting in touch, such as a lost card, a pending transfer, or a question about exchange rates. The messages are brief and many of the reasons are close cousins of one another, so telling them apart is much harder than sorting news by topic.

“I need to reorder my virtual card!”
Correct label: Getting virtual card

Every classifier was given the same 1,000 messages, drawn from the test set with the 77 labels spread as evenly as possible. None of these messages were used to train any of the models. Each classifier returned one label per message and, in most cases, a confidence score.

The classifiers differ in how much they were told about the task before the test, and that matters as much as the model itself when comparing scores:

  • Zero-shot (19): given only the label names, never an example
  • In-domain checkpoint (4): released models whose own training already included this task's data
  • Classical supervised (7): word-count (TF-IDF) or embedding features with a simple classifier, fitted on the task's training examples
  • Fine-tuned encoder (2): pre-trained language models adapted to the task with its training examples
  • From scratch (3): neural networks trained only on the task's training examples, starting from random weights

One of them ran on a remote service rather than the test machine, so its times include the network and unknown hardware.

Main findings

The top two classifiers all scored 94%: DeBERTa-v3-base, fine-tuned (supervised) and ModernBERT-base, fine-tuned (supervised). When the 1,000 messages are resampled (the paired bootstrap in the full report), each of them comes first often enough that their order here should not be read as a ranking.

How to read the numbers

Accuracy
The share of messages the classifier labeled correctly. 90% means 9 out of 10 were right.
Accuracy range (95% CI)
A statistical estimate (Wilson 95% confidence interval) of the uncertainty in the measured accuracy. With only 1,000 messages, the true accuracy could plausibly be higher or lower than the measured figure. Each interval describes one classifier on its own; it is not a test of whether two classifiers differ, and overlapping intervals do not mean two classifiers are equal. The full report has paired tests for that.
Average time per message (batched)
Total classification time divided by the number of messages, with each classifier processing the sample in its usual batches or parallel requests. Model loading is not included. This measures throughput: it is not how long one request takes.
Single request
The median time to classify one item sent on its own, which is what a user waiting for one answer experiences. A dash means it was not measured in this run.
Memory
The most memory the classifier used while running, including any separate model server. A dash means it was not measured, for example for an online service.

Speed versus accuracy

Average batched times range from 17 µs per message (fastText-style network, trained from scratch (supervised)) to 5.6 s (Decision 3.0 edge (0.59B)), a factor of about 300,000. These are throughput figures, not response times. Sent one message at a time, 16 of the 35 classifiers with both measurements took more than twice their batched average; the largest gap is TF-IDF + Linear SVM, calibrated (supervised), at 65 µs batched against 5.5 ms for a single request.

Six classifiers are on the speed–accuracy frontier: no other classifier is both faster (batched) and more accurate. Every classifier not listed is beaten on both counts by at least one that is.

  • fastText-style network, trained from scratch (supervised): 88% correct, 17 µs per message batched, 37 µs single request
  • TextCNN, trained from scratch (supervised): 89% correct, 28 µs per message batched, 481 µs single request
  • TF-IDF + Linear SVM, uncalibrated (supervised): 91% correct, 50 µs per message batched, 413 µs single request
  • TF-IDF + LogReg (supervised): 92% correct, 51 µs per message batched, 427 µs single request
  • ModernBERT-base, fine-tuned (supervised): 94% correct, 4.1 ms per message batched, 8.6 ms single request
  • DeBERTa-v3-base, fine-tuned (supervised): 94% correct, 5.1 ms per message batched, 19 ms single request

All local times come from one machine (Apple M5); the order of the faster classifiers can change on other hardware.

Where classifiers go wrong

Averaged over all classifiers, the hardest labels were Beneficiary not allowed (45%), Top up by bank transfer charge (45%), Balance not updated after bank transfer (50%), Get physical card (51%) and Direct debit payment not recognised (51%), while Passcode forgotten, Terminate account and Verify source of funds were almost always spotted.

The most common mix-ups, counted across all 35 classifiers:

  • Card payment wrong exchange rate messages labeled as Exchange rate: 96 times, made by 24 of the 35 classifiers
  • Why verify identity messages labeled as Verify my identity: 90 times, made by 18 of the 35 classifiers
  • Exchange charge messages labeled as Exchange rate: 88 times, made by 33 of the 35 classifiers

The reverse of the first mix-up is much rarer (8 times), so when unsure between the two, classifiers lean towards Exchange rate.

Knowing when to trust an answer

A confidence score allows a split workflow: the classifier answers the messages it is confident about and passes the rest to a person. For each classifier, the confidence cut-off for a 95% accuracy target was chosen on one set of messages and then checked on different ones, so the figures below are not tuned to the items they are measured on.

DeBERTa-v3-base, fine-tuned (supervised) answered 95% of the messages on its own and was 97% correct on them, followed by ModernBERT-base, fine-tuned (supervised) (94%) and TF-IDF + LogReg (supervised) (91%).

Cut-offs were chosen by cross-fitting: the sample was split in half, and each half was scored with the cut-off chosen on the other. With about 500 messages per half these figures are rough; a separate calibration run gives firmer ones.

Before you draw conclusions

  • The test is a sample. With 1,000 messages, an accuracy near 90% is only known to within about ±2 points. That separates good classifiers from poor ones, but not classifiers a few points apart.
  • Scores describe this setup. Some classifiers learned from labeled examples of this task and others from none; some ran locally and others on a remote service. A higher score means better under these conditions, not a better model in general.
  • Results belong to this task. A classifier that does well on Banking77 may do worse on different text or different labels; compare with the other benchmark task.
  • Speed depends on hardware and how the classifier is called. Batched averages measure throughput, and single-request times measure response time. Both come from one machine.
