About this model

In this project the model is registered as kev, and its code is in classifiers/kev/.

The model accepts at most 255 labels in one question. AG News has 4 labels and Banking77 has 77, so both tasks fit.

03

Getting the model

The official page is huggingface.co/jaredpalmer/kev-0.8b. The setup script pins exact revisions in classifiers/kev/setup.sh or classifier.py. Use the setup script instead of downloading the latest revision by hand, because a different revision can give different results.

shell
./run setup kev

The setup script creates classifiers/kev/.venv, installs requirements.txt, downloads the pinned weights, and runs the adapter's checks where it has them (probe texts, and for some entries a comparison of GPU and CPU scores).

04

Installing from a clean checkout

shell
cd /path/to/Classification
runner/setup.sh        # the runner's own environment
cp .env.example .env    # then edit the settings you need
./run list
./run setup kev

The reference platform is macOS on Apple Silicon. Requirements for memory, GPU, Ollama, servers and API keys differ between entries, and ./run list states what is missing for each one. If a check fails during setup, fix the cause instead of skipping the check. Keep API keys in .env. Do not put them in HTML files or commit them.

05

Sending data and reading results

Input format

  • Labels: a Python dict that maps each label ID to a short description. The ID is what the model returns. The description is what the model reads, so it should say clearly what belongs in that label.
  • Instruction: one question that tells the model what decision to make, for example What is the topic of this news article?.
  • Text: one string per call to predict, or a list of strings for predict_many, which batches them.

The benchmark builds the labels from the task manifest in data/tasks/. For your own labels, pass your own dictionary. Use IDs without spaces, because the evaluator writes one column named p_<id> per label.

Calling it from Python

Run Python from the entry's folder with its own environment. PYTHONPATH must point at shared/, because the adapter imports the task loader from there.

shell
cd classifiers/kev
PYTHONPATH=../../shared .venv/bin/python my_script.py
python
from classifier import KevClassifier

labels = {
    "world": "International news, politics, government, conflicts, diplomacy, elections",
    "sports": "Sports events, athletes, teams, games, tournaments, leagues",
    "business": "Companies, markets, economy, finance, earnings, trade, oil prices, mergers",
    "sci_tech": "Science, technology, computing, internet, software, space, health research",
}
instruction = "What is the topic of this news article?"

clf = KevClassifier(labels, instruction)

p = clf.predict("Stocks rallied after the central bank decision.")
print(p.label)          # the label ID with the highest score
print(p.confidence)     # a number from 0 to 1
print(p.probabilities)  # one score per label ID

many = clf.predict_many(["First text.", "Second text."])  # Predictions, in order

Output format

predict returns a Prediction object with three fields:

  • label: the chosen label ID. It is always a label with the highest score.
  • confidence: a number from 0 to 1. For this entry it is defined as: max p (release temperature).
  • probabilities: a dict from every label ID to its probability estimate. Confidence type: Release temperature.

What goes over the wire

Nothing. The model runs inside the Python process, so there is no server or HTTP request. The only network access is the one-time download during setup.

Benchmark output

The benchmark evaluator writes one prediction CSV per run to the entry's results folder, in the format described in What every entry shares.

What it learns from the task

Approach in the score reports: in-domain checkpoint. Nothing is fitted for the benchmark. The released checkpoint already saw AG News and Banking77 data in its own training, so the reports list it as an in-domain checkpoint on both bundled tasks.

The data preparation, sampling and calibration sample sizes are the same for every entry: see What every entry shares.

08

Training and adaptation

In-domain

The released checkpoint was trained on data from ag_news and banking77. Its results on those tasks are not zero-shot results.

You do not need to fine-tune it for this benchmark. During setup, an overlap check compares our test texts with the model's training data and writes results/overlap.json. Test texts that also appear in the dataset's own train split do not count, because the supervised baselines see them too. If other test texts appear in the training data, or the check has not run, the runner skips the task.

For a new domain, first try clearer label descriptions. If you retrain, use the model author's own training code, keep this project's test split out of training, prefer LoRA or another parameter-efficient method for large models, choose epochs and learning rate on validation data, calibrate on a separate part of the train split, and register the result as a new entry so its results stay separate from the release.
