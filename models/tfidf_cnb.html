03

Getting the model

The official page is scikit-learn.org/stable/modules/naive_bayes.html#complement-naive-bayes.

shell
./run setup tfidf_cnb

There are no pretrained weights. The setup script creates the virtual environment and installs scikit-learn. The model is fitted on the task's train split the first time you run it, and the fit is cached in results/cache/.

04

Installing from a clean checkout

shell
cd /path/to/Classification
runner/setup.sh        # the runner's own environment
cp .env.example .env    # then edit the settings you need
./run list
./run setup tfidf_cnb

The reference platform is macOS on Apple Silicon. Requirements for memory, GPU, Ollama, servers and API keys differ between entries, and ./run list states what is missing for each one. If a check fails during setup, fix the cause instead of skipping the check. Keep API keys in .env. Do not put them in HTML files or commit them.

05

Sending data and reading results

Input format

A supervised classifier learns its labels from the training data, so you do not pass a label list. The labels and the train split come from the task manifest selected by BENCHMARK_TASK (default ag_news). To classify, you pass one string, or a list of strings to predict_many.

Calling it from Python

Run Python from the entry's folder with its own environment. PYTHONPATH must point at shared/, because the adapter imports the task loader from there.

shell
cd classifiers/tfidf_cnb
PYTHONPATH=../../shared .venv/bin/python my_script.py
python
from classifier import *  # the class and the train loaders

train = load_train_set()
clf = TfidfCNBClassifier().fit(train["text"].tolist(), train["label"].tolist())

p = clf.predict("Stocks rallied after the central bank decision.")
print(p.label)          # the label ID with the highest score
print(p.confidence)     # a number from 0 to 1
print(p.probabilities)  # one score per label ID

many = clf.predict_many(["First text.", "Second text."])  # Predictions, in order

This example fits with the default hyperparameters. The benchmark evaluator instead chooses them by cross-validation on the train split and stores the choice in classifiers/tfidf_cnb/hyperparameters.json.

Output format

predict returns a Prediction object with three fields:

  • label: the chosen label ID. It is always a label with the highest score.
  • confidence: a number from 0 to 1. For this entry it is defined as: max p (native, uncalibrated NB).
  • probabilities: normalized scores for every label ID (a dict). They sum to 1 but are not calibrated probability estimates. Confidence type: Normalized score.

What goes over the wire

Nothing. The model runs inside the Python process, so there is no server or HTTP request. The only network access is the one-time download during setup.

Benchmark output

The benchmark evaluator writes a CSV file of predictions to the entry's results folder. It has one row per test text and these columns: sample_id, text, label (the true label), pred, confidence, and one p_<label> column per label. runner/validate.py checks that the rows match the expected sample, that every label is known, that each row's probabilities sum to 1, and that pred has the highest probability.

06

How the benchmark prepares data

Every entry receives the same data in the same way. This makes the results comparable.

  1. shared/task.py loads the task manifest, data/tasks/ag_news.json or data/tasks/banking77.json.
  2. On first use it downloads the CSV files named in the manifest, if they are not present, and verifies their SHA-256 checksums.
  3. The raw columns are converted to exactly two: text and label. For AG News the text is the title and the description joined as {title}. {description}. Banking77 uses its text column.
  4. The runner draws the same label-balanced test sample for every entry, chosen by --n and --seed.
  5. The adapter receives the label IDs, names, descriptions and the task instruction. Supervised models fit on the train split. Zero-shot models fit nothing that changes their decision. A few (confidence type task-calibrated) fit one confidence temperature on a fixed labeled sample drawn from the train split: their accuracy remains zero-shot, but their confidence and calibration metrics are task-calibrated.
TaskLabelsTextCalibration sampleSupervised sample
AG News4 topicstitle and description100 train rows per label1,000 rows per label

To use your own data, copy a manifest in data/tasks/, give the train and test files or URLs with their checksums, map every raw label to an ID, and write a short description for each label that separates it from the others. Only single-label classification is supported.

07

Running the benchmark

shell
./run tfidf_cnb --task ag_news --n 200
./run tfidf_cnb --task banking77 --n 200

--n 0 runs the whole test split. --seed N draws a different but reproducible sample. --dry-run prints the resolved command without running it. Options for the adapter itself go after --.

Inside the full benchmark

shell
./run all --task ag_news --only tfidf_cnb
./run report --task ag_news

The first command runs only this entry and then rebuilds the report. The second rebuilds the report from results that already exist.

08

Training and adaptation

Training

Training is required, and the evaluator does it automatically. The evaluator builds the TF-IDF features and fits the estimator on the train split. The hyperparameters are chosen by 3-fold stratified cross-validation on the train split only, and the fit is cached together with a fingerprint of the data and the scikit-learn version.

  1. Keep the labels and examples in the task manifest and its train file.
  2. Run the benchmark command. Fitting happens before any test text is classified.
  3. The chosen hyperparameters are in classifiers/tfidf_cnb/hyperparameters.json, and cached fits are in results/cache/.
  4. After the data changes, run again. The fingerprint prevents an old fit from being reused. Delete the cache only when you want to force a new fit.

Never tune on data/*_test.csv. Choose settings with cross-validation or a validation part of the train split, and evaluate the final choice once on the test split.

09

Reading the results

Accuracy tells you how often the top label was correct. It does not tell you which labels the model confuses. For that, the report also shows a confusion matrix, scores per class, calibration and error analysis, latency, memory use, and selective prediction (accuracy when only confident answers are kept). Compare two runs only when the task, sample size, seed and model revision are the same.

A high confidence value does not guarantee a correct answer. For this entry, confidence is defined as: max p (native, uncalibrated NB).

When something goes wrong

  • ./run list --task ag_news shows whether the entry is ready and, if not, why.
  • Run ./run setup tfidf_cnb again after changing Python or dependencies.
  • Check .env.example for this entry's host, model, device, key and context settings.
  • ./run tfidf_cnb --dry-run shows the arguments the runner passes.
  • ModuleNotFoundError: No module named 'task' (or 'training') when running classifier.py directly means PYTHONPATH=../../shared is missing.
  • Out-of-memory errors, truncated options and unreachable services are setup problems, not measures of model quality.
