01

About this model

In this project the model is registered as embedsup_centroid, and its code is in classifiers/embedsup/. This entry passes --method centroid to the evaluator. Other entries that use the same folder: embedsup_logreg.

This entry computes one centroid per class. A temperature fitted on a held-out 20% of the train sample turns the cosine similarities into probabilities, and the centroids are then recomputed on the whole sample.

How it works

ModelBGE-M3 with a supervised head
PublisherBAAI (embeddings), scikit-learn (head)
Weights or servicebge-m3:567m (Ollama) plus a head fitted on the task's train split

03

Getting the model

The official page is ollama.com/library/bge-m3. The setup script pins exact revisions in classifiers/embedsup/setup.sh or classifier.py. Use the setup script instead of downloading the latest revision by hand, because a different revision can give different results.

shell
./run setup embedsup_centroid

The setup script creates classifiers/embedsup/.venv, installs requirements.txt, downloads the pinned weights, and runs the adapter's checks where it has them (probe texts, and for some entries a comparison of GPU and CPU scores).

Ollama models are pulled with ollama pull bge-m3:567m. The setup script does this when Ollama is running.

cp .env.example .env    # then edit the settings you need

The reference platform is macOS on Apple Silicon. Requirements for memory, GPU, Ollama, servers and API keys differ between entries, and ./run list states what is missing for each one. If a check fails during setup, fix the cause instead of skipping the check. Keep API keys in .env. Do not put them in HTML files or commit them.

05

Sending data and reading results

Input format

A supervised classifier learns its labels from the training data, so you do not pass a label list. The labels and the train split come from the task manifest selected by BENCHMARK_TASK (default ag_news). To classify, you pass one string, or a list of strings to predict_many.

Calling it from Python

Run Python from the entry's folder with its own environment. PYTHONPATH must point at shared/, because the adapter imports the task loader from there.

shell
cd classifiers/embedsup
PYTHONPATH=../../shared .venv/bin/python my_script.py
python
from classifier import *  # the class and the train loaders

clf = EmbedSupClassifier(method="centroid")
train = load_train_sample(per_class=1000, seed=0)
vectors, _, _ = clf.embed_train(train, seed=0)  # cached in results/cache/
clf.fit(vectors, train["label"].tolist())

p = clf.predict("Stocks rallied after the central bank decision.")
print(p.label)          # the label ID with the highest score
print(p.confidence)     # a number from 0 to 1
print(p.probabilities)  # one score per label ID

many = clf.predict_many(["First text.", "Second text."])  # Predictions, in order

Output format

predict returns a Prediction object with three fields:

  • label: the chosen label ID. It is always a label with the highest score.
  • confidence: a number from 0 to 1. For this entry it is defined as: max p (temperature fitted on held-out train).
  • probabilities: a dict from every label ID to its probability estimate. Confidence type: Task-calibrated.

What goes over the wire

Only the embeddings come from Ollama. The adapter sends texts in batches to the embedding endpoint and does the rest of the work in Python.

http
POST http://OLLAMA_HOST/api/embed

{"model": "bge-m3:567m", "input": ["Stocks rallied after the central bank decision.", "..."]}

response: {"embeddings": [[0.0123, -0.0456, ...], ...]}   # one 1024-number vector per input

Training embeddings are cached in results/cache/ together with the model tag and its Ollama digest. A re-pulled model is embedded again.

Benchmark output

The benchmark evaluator writes one prediction CSV per run to the entry's results folder, in the format described in What every entry shares.

08

Training and adaptation

Training

Training is required, and the evaluator does it automatically. The BGE-M3 encoder is not changed. The evaluator embeds a fixed, stratified sample of the train split and fits either class centroids or a logistic regression on the vectors. For the centroid method, the temperature is fitted on a held-out part of that sample.

  1. Keep the labels and examples in the task manifest and its train file.
  2. Run the benchmark command. Fitting happens before any test text is classified.
  3. The chosen hyperparameters are in classifiers/embedsup/hyperparameters.json, and cached fits are in results/cache/.
  4. After the data changes, run again. The fingerprint prevents an old fit from being reused. Delete the cache only when you want to force a new fit.

Never tune on data/*_test.csv. Choose settings with cross-validation or a validation part of the train split, and evaluate the final choice once on the test split.

When something goes wrong

  • ./run embedsup_centroid --dry-run shows the arguments the runner passes to this entry.
  • Run ./run setup embedsup_centroid again after changing Python or dependencies.
  • "Ollama not reachable" means Ollama is not running at the configured host. "not pulled" means the model tag must be pulled first.
