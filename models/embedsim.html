Models/010/embedsim

Embedding similarity (bge-m3)

BGE-M3 turns the input text and each label description into vectors. The label whose vector has the highest cosine similarity to the text is chosen. A temperature fitted on training data turns the similarities into probabilities.

01

About this model

In this project the model is registered as embedsim, and its code is in classifiers/embedsim/.

There is no hard adapter limit on the number of labels. Practical capacity is still constrained by context length, label-description truncation, memory, runtime and model quality, so validate large label sets separately.

03

Getting the model

The official page is ollama.com/library/bge-m3. The setup script pins exact revisions in classifiers/embedsim/setup.sh or classifier.py. Use the setup script instead of downloading the latest revision by hand, because a different revision can give different results.

shell
./run setup embedsim

The setup script creates classifiers/embedsim/.venv, installs requirements.txt, downloads the pinned weights, and runs the adapter's checks where it has them (probe texts, and for some entries a comparison of GPU and CPU scores).

Ollama models are pulled with ollama pull bge-m3:567m. The setup script does this when Ollama is running.

04

Installing from a clean checkout

shell
cd /path/to/Classification
runner/setup.sh        # the runner's own environment
cp .env.example .env    # then edit the settings you need
./run list
./run setup embedsim

The reference platform is macOS on Apple Silicon. Requirements for memory, GPU, Ollama, servers and API keys differ between entries, and ./run list states what is missing for each one. If a check fails during setup, fix the cause instead of skipping the check. Keep API keys in .env. Do not put them in HTML files or commit them.

05

Sending data and reading results

Input format

  • Labels: a Python dict that maps each label ID to a short description. The ID is what the model returns. The description is what the model reads, so it should say clearly what belongs in that label.
  • Instruction: this adapter does not take one. It reads only the text and the labels.
  • Text: one string per call to predict, or a list of strings for predict_many, which batches them.

The benchmark builds the labels from the task manifest in data/tasks/. For your own labels, pass your own dictionary. Use IDs without spaces, because the evaluator writes one column named p_<id> per label.

Calling it from Python

Run Python from the entry's folder with its own environment. PYTHONPATH must point at shared/, because the adapter imports the task loader from there.

shell
cd classifiers/embedsim
PYTHONPATH=../../shared .venv/bin/python my_script.py
python
from classifier import EmbedSimClassifier

labels = {
    "world": "International news, politics, government, conflicts, diplomacy, elections",
    "sports": "Sports events, athletes, teams, games, tournaments, leagues",
    "business": "Companies, markets, economy, finance, earnings, trade, oil prices, mergers",
    "sci_tech": "Science, technology, computing, internet, software, space, health research",
}

clf = EmbedSimClassifier(labels)

p = clf.predict("Stocks rallied after the central bank decision.")
print(p.label)          # the label ID with the highest score
print(p.confidence)     # a number from 0 to 1
print(p.probabilities)  # one score per label ID

many = clf.predict_many(["First text.", "Second text."])  # Predictions, in order

Output format

predict returns a Prediction object with three fields:

  • label: the chosen label ID. It is always a label with the highest score.
  • confidence: a number from 0 to 1. For this entry it is defined as: max p (fitted temperature).
  • probabilities: a dict from every label ID to its probability estimate. Confidence type: Task-calibrated.

What goes over the wire

Only the embeddings come from Ollama. The adapter sends texts in batches to the embedding endpoint and does the rest of the work in Python.

http
POST http://OLLAMA_HOST/api/embed

{"model": "bge-m3:567m", "input": ["Stocks rallied after the central bank decision.", "..."]}

response: {"embeddings": [[0.0123, -0.0456, ...], ...]}   # one 1024-number vector per input

For embedsim the label descriptions are embedded with the template {name} news: {description} from the task manifest, and each text gets softmax(cosine / T) over the labels.

Benchmark output

The benchmark evaluator writes one prediction CSV per run to the entry's results folder, in the format described in What every entry shares.

06

What it learns from the task

Approach in the score reports: zero-shot. Its decision uses only the label descriptions. One confidence temperature is fitted on the fixed labeled calibration sample from the train split, so its accuracy is zero-shot but its confidence figures are task-calibrated.

The data preparation, sampling and calibration sample sizes are the same for every entry: see What every entry shares.

08

Training and adaptation

No fine-tuning

The method is zero-shot. Only the label text and, where used, a calibration temperature fitted on train data are adapted.

Write distinct label descriptions before trying a different model. Where this entry uses a temperature, it is one positive scalar applied uniformly to all label logits: it changes the normalized confidence values but not which label has the largest score. If you need a model trained on your domain, add it as a separate entry and evaluate it on a test split it has never seen.

When something goes wrong

  • ./run embedsim --dry-run shows the arguments the runner passes to this entry.
  • Run ./run setup embedsim again after changing Python or dependencies.
  • "Ollama not reachable" means Ollama is not running at the configured host. "not pulled" means the model tag must be pulled first.
