Winnow-12B (Gemma 4 12B, Q8_0)

Winnow-12B is a decision fine-tune of Gemma 4 12B, quantized to Q8_0 and served by llama.cpp on Metal. The runner starts and stops the server for each benchmark run. One question can carry 2 to 64 options.

About this model

In this project the model is registered as winnow, and its code is in classifiers/winnow/. Other entries that use the same folder: winnow_shortlist.

The model accepts at most 64 labels in one question. AG News has 4 labels and Banking77 has 77, so Banking77 cannot be run directly. Use winnow_shortlist for Banking77.

03

Getting the model

The official page is huggingface.co/EldanRing/Winnow-12B. The setup script pins exact revisions in classifiers/winnow/setup.sh or classifier.py. Use the setup script instead of downloading the latest revision by hand, because a different revision can give different results.

shell
./run setup winnow

The setup script also prepares the llama.cpp server in server/ and downloads the Q8_0 GGUF file. The runner starts and stops the server during benchmark runs.

04

Installing from a clean checkout

shell
cd /path/to/Classification
runner/setup.sh        # the runner's own environment
cp .env.example .env    # then edit the settings you need
./run list
./run setup winnow

The reference platform is macOS on Apple Silicon. Requirements for memory, GPU, Ollama, servers and API keys differ between entries, and ./run list states what is missing for each one. If a check fails during setup, fix the cause instead of skipping the check. Keep API keys in .env. Do not put them in HTML files or commit them.

05

Sending data and reading results

Input format

  • Labels: a Python dict that maps each label ID to a short description. The ID is what the model returns. The description is what the model reads, so it should say clearly what belongs in that label.
  • Instruction: one question that tells the model what decision to make, for example What is the topic of this news article?.
  • Text: one string per call to predict, or a list of strings for predict_many, which batches them.

The benchmark builds the labels from the task manifest in data/tasks/. For your own labels, pass your own dictionary. Use IDs without spaces, because the evaluator writes one column named p_<id> per label.

Calling it from Python

Run Python from the entry's folder with its own environment. PYTHONPATH must point at shared/, because the adapter imports the task loader from there.

shell
cd classifiers/winnow
PYTHONPATH=../../shared .venv/bin/python my_script.py
python
from classifier import WinnowClassifier

labels = {
    "world": "International news, politics, government, conflicts, diplomacy, elections",
    "sports": "Sports events, athletes, teams, games, tournaments, leagues",
    "business": "Companies, markets, economy, finance, earnings, trade, oil prices, mergers",
    "sci_tech": "Science, technology, computing, internet, software, space, health research",
}
instruction = "What is the topic of this news article?"

clf = WinnowClassifier(labels, instruction)

p = clf.predict("Stocks rallied after the central bank decision.")
print(p.label)          # the label ID with the highest score
print(p.confidence)     # a number from 0 to 1
print(p.probabilities)  # one score per label ID

many = clf.predict_many(["First text.", "Second text."])  # Predictions, in order

Output format

predict returns a Prediction object with three fields:

  • label: the chosen label ID. It is always a label with the highest score.
  • confidence: a number from 0 to 1. For this entry it is defined as: max p.
  • probabilities: normalized scores for every label ID (a dict). They sum to 1 but are not calibrated probability estimates. Confidence type: Normalized score.

What goes over the wire

The Python class sends one HTTP request per text to the server at http://127.0.0.1:8091. The request is a "choice question" in the Jev format: the text goes in state, and the labels go in criteria as ID and description pairs. Winnow keys the options by label name (for example Science/Technology), and the adapter maps the names back to label IDs. Before a run, the adapter checks the server with GET /health.

http
POST http://127.0.0.1:8091/v1/systemone
Content-Type: application/json
Authorization: Bearer <key>   (only when an API key is set)

{
  "model": "Winnow-12B",
  "state": "Stocks rallied after the central bank decision.",
  "questions": {
    "label": {
      "type": "choice",
      "instructions": "What is the topic of this news article?",
      "criteria": {
        "World": "International news, politics, government, conflicts, diplomacy, elections",
        "Sports": "Sports events, athletes, teams, games, tournaments, leagues",
        "Business": "Companies, markets, economy, finance, earnings, trade, oil prices, mergers",
        "Science/Technology": "Science, technology, computing, internet, software, space, health research"
      }
    }
  }
}

The server replies with the chosen option, its confidence and the probability of every option (the numbers below are from this entry's recorded sample):

json
{
  "answers": {
    "label": {
      "choice": "Business",
      "confidence": 0.9995,
      "probabilities": {
        "Business": 0.9995,
        "World": 0.0004,
        "Science/Technology": 0.0001,
        "Sports": 0.0
      }
    }
  },
  "usage": {"input_tokens": ..., "output_tokens": ...}
}

Failed requests (connection errors, HTTP 429 and server errors) are retried with a growing delay. You can call the server from any language with the same JSON.

Benchmark output

The benchmark evaluator writes a CSV file of predictions to the entry's results folder. It has one row per test text and these columns: sample_id, text, label (the true label), pred, confidence, and one p_<label> column per label. runner/validate.py checks that the rows match the expected sample, that every label is known, that each row's probabilities sum to 1, and that pred has the highest probability.

06

How the benchmark prepares data

Every entry receives the same data in the same way. This makes the results comparable.

  1. shared/task.py loads the task manifest, data/tasks/ag_news.json or data/tasks/banking77.json.
  2. On first use it downloads the CSV files named in the manifest, if they are not present, and verifies their SHA-256 checksums.
  3. The raw columns are converted to exactly two: text and label. For AG News the text is the title and the description joined as {title}. {description}. Banking77 uses its text column.
  4. The runner draws the same label-balanced test sample for every entry, chosen by --n and --seed.
  5. The adapter receives the label IDs, names, descriptions and the task instruction. Supervised models fit on the train split. Zero-shot models fit nothing that changes their decision. A few (confidence type task-calibrated) fit one confidence temperature on a fixed labeled sample drawn from the train split: their accuracy remains zero-shot, but their confidence and calibration metrics are task-calibrated.

To use your own data, copy a manifest in data/tasks/, give the train and test files or URLs with their checksums, map every raw label to an ID, and write a short description for each label that separates it from the others. Only single-label classification is supported.

07

Running the benchmark

shell
./run winnow --task ag_news --n 200

--n 0 runs the whole test split. --seed N draws a different but reproducible sample. --dry-run prints the resolved command without running it. Options for the adapter itself go after --.

Inside the full benchmark

shell
./run all --task ag_news --only winnow
./run report --task ag_news

The first command runs only this entry and then rebuilds the report. The second rebuilds the report from results that already exist.

08

Training and adaptation

No fine-tuning

This adapter uses a released, already trained checkpoint and applies it to the label set. No training is part of the benchmark.

If the results are poor on your data, first improve the label names and descriptions in the manifest. Fine-tuning is possible but is outside this adapter. If you do it, use the training procedure from the official project page, keep the test data out of training, use a train and validation split, prefer a parameter-efficient adapter for models with billions of parameters, calibrate probabilities on held-out train data, and register the new checkpoint as a separate entry. Do not replace the pinned release, because earlier results could then no longer be reproduced.

09

Reading the results

Accuracy tells you how often the top label was correct. It does not tell you which labels the model confuses. For that, the report also shows a confusion matrix, scores per class, calibration and error analysis, latency, memory use, and selective prediction (accuracy when only confident answers are kept). Compare two runs only when the task, sample size, seed and model revision are the same.

A high confidence value does not guarantee a correct answer. For this entry, confidence is defined as: max p.

When something goes wrong

  • ./run list --task ag_news shows whether the entry is ready and, if not, why.
  • Run ./run setup winnow again after changing Python or dependencies.
  • Check .env.example for this entry's host, model, device, key and context settings.
  • ./run winnow --dry-run shows the arguments the runner passes.
  • ModuleNotFoundError: No module named 'task' (or 'training') when running classifier.py directly means PYTHONPATH=../../shared is missing.
  • If Banking77 is refused because it has too many labels, use the _shortlist entry when one exists.
  • "Cannot reach" or "not ready" means the server is not running or is still loading the model.
  • Out-of-memory errors, truncated options and unreachable services are setup problems, not measures of model quality.
