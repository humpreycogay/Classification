01

About this model

In this project the model is registered as winnow_shortlist, and its code is in classifiers/winnow/. This entry passes --shortlist 64 to the evaluator. Other entries that use the same folder: winnow.

This is a two-stage entry. BGE-M3 first compares the text with every label description and keeps the 64 closest labels. The model then chooses among those 64. If the correct label is not in the shortlist, the model cannot choose it, so the shortlist's recall is the highest accuracy this entry can reach.

How the main model works

After the shortlist stage (see Sending data and reading results), the main model works as below, on the 64 kept labels only.

03

Getting the model

The official page is huggingface.co/EldanRing/Winnow-12B. The setup script pins exact revisions in classifiers/winnow/setup.sh or classifier.py. Use the setup script instead of downloading the latest revision by hand, because a different revision can give different results.

shell
./run setup winnow_shortlist

The setup script also prepares the llama.cpp server in server/ and downloads the Q8_0 GGUF file. The runner starts and stops the server during benchmark runs.

Ollama models are pulled with ollama pull bge-m3:567m. The setup script does this when Ollama is running.

Installing from a clean checkout

cp .env.example .env    # then edit the settings you need

The reference platform is macOS on Apple Silicon. Requirements for memory, GPU, Ollama, servers and API keys differ between entries, and ./run list states what is missing for each one. If a check fails during setup, fix the cause instead of skipping the check. Keep API keys in .env. Do not put them in HTML files or commit them.

05

Sending data and reading results

How the two stages work

For each text, BGE-M3 (through Ollama) ranks all labels by cosine similarity between the text and the label descriptions. The 64 closest labels are passed to the model as an ordinary label set. The output dictionary still has every task label: labels excluded by the shortlist are assigned 0 as placeholders, and the remaining values are the main model's normalized scores within the shortlist. The input and output formats of the model itself are described on the winnow page.

The two stages at a glance

Calling it from Python

The benchmark evaluator does both stages for you. To do them in your own code, build a Shortlister from shared/shortlist.py, then pass each text's shortlisted labels to predict_shortlisted, which every shortlist-capable classifier has.

shell
cd classifiers/winnow
BENCHMARK_TASK=banking77 PYTHONPATH=../../shared .venv/bin/python my_script.py
python
from task import current_task
from shortlist import Shortlister
from classifier import WinnowClassifier

task = current_task()  # run with BENCHMARK_TASK=banking77
labels = {s["id"]: s["description"] for s in task.labels}  # all 77 intents
k = 64

shortlister = Shortlister(task, k)  # stage 1: embeds the 77 label texts with bge-m3 (Ollama)
clf = WinnowClassifier(dict(list(labels.items())[:k]), task.instruction)  # stage 2, built for k labels

text = "I ordered a new card two weeks ago and it still has not arrived."
keep = shortlister.top_k([text])[0]  # the k label IDs closest to the text
p = clf.predict_shortlisted([text], [{l: labels[l] for l in keep}])[0]
print(keep)
print(p.label, p.confidence)

Running it on the benchmark

shell
./run winnow_shortlist --task banking77 --n 200

The run metadata records the shortlist's recall: the share of texts whose correct label was kept, measured on the calibration split and on the test sample. That share is the highest accuracy the entry can reach.

Benchmark output

The benchmark evaluator writes one prediction CSV per run to the entry's results folder, in the format described in What every entry shares.

06

What it learns from the task

Approach in the score reports: zero-shot. Nothing is fitted on task data: it decides from the label names and descriptions alone. An embedding model first narrows the labels to 64 candidates, and this entry chooses among them.

The data preparation, sampling and calibration sample sizes are the same for every entry: see What every entry shares.

08

Training and adaptation

No fine-tuning

This adapter uses a released, already trained checkpoint and applies it to the label set. No training is part of the benchmark.

If the results are poor on your data, first improve the label names and descriptions in the manifest. Fine-tuning is possible but is outside this adapter. If you do it, use the training procedure from the official project page, keep the test data out of training, use a train and validation split, prefer a parameter-efficient adapter for models with billions of parameters, calibrate probabilities on held-out train data, and register the new checkpoint as a separate entry. Do not replace the pinned release, because earlier results could then no longer be reproduced.

When something goes wrong

  • ./run winnow_shortlist --dry-run shows the arguments the runner passes to this entry.
  • Run ./run setup winnow_shortlist again after changing Python or dependencies.
  • "Cannot reach" or "not ready" means the server is not running or is still loading the model.
  • "Ollama not reachable" means Ollama is not running at the configured host. "not pulled" means the model tag must be pulled first.

Problems common to every entry are listed in What every entry shares.
